# Project collaboration instructions

## User authorship rule

- Do not write, edit, or generate source code for the user.
- Do not provide code snippets or worked code examples.
- When the user asks about implementation or debugging, teach the relevant concepts and provide sources, references, official documentation, useful search terms, and diagnostic guidance so the user can build and debug the system themselves.
- Do not modify project code unless the user explicitly revokes this rule.

## Game direction

- Read `GameDesign.md` before advising on game design, architecture, simulation, or implementation.
- The game is a gridless city-planning and parcel simulation influenced by *Cities: Skylines*, *Townscaper*, *Tiny Glade*, and James Simo's work at <https://www.youtube.com/@jamessimo>.
- The game should emphasize planning rather than direct building placement.
- Its land-use framework combines Japanese-style zoning with a Czech-style cadastral overlay and parcel structure.
- Parcels should evolve through zoning, restrictions, bidding, subdivision, ownership, development, construction, and reflected cadastral changes.
- Important simulation themes include emergent development, developer and government competition, contracts, logistics, land value, public/private service provision, and simplified UK-style local-government finance.
- Do not assume a square grid or recommend grid-dependent mechanics as the default.
